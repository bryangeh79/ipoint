- **Cells:** 1.1 (admin-web ↔ API permissions)
- **Severity:** L (Low) — no security impact; UI gate is stricter than server, never looser. MFA enrollment/recovery and session self-service routes are guarded by `AdminGuard` (authenticated admin) which is the correct security posture for self-service surfaces; the catalog codes exist and would matter if a role-based restriction were ever required.
- **Evidence:** `route-manifest.ts` (mfa-enroll, mfa-recovery, sessions routes); `admin-auth.controller.ts:226` (`@Controller('admin/sessions')` + class `@UseGuards(AdminGuard)`); catalog contains both codes (`permission-catalog.ts:70,83`); API `@RequirePermission` usage scan shows neither (`.local/p8-s5e/perm-scan.txt`).
- **Disposition:** documented only (drift class per §11; fixing would touch API production code — out of scope, no defect to repair).

- **Severity:** L — forward-defensive mappings from the P7-S1 DRAFT register; none swallows a real API error (verified: every API-producible mapped code resolves correctly; unknown codes fall through to verbatim display). No user-visible break.
