## 1. Route conventions

Role abbreviations: `SA` Super Admin; `OA` Operations Admin; `FO` Finance Operator; `FA` Finance Approver; `KR` KYC Reviewer; `SR` Support / Read-only Auditor. Every protected route also requires an active eligible Admin, accepted MFA, an active role assignment, the stated permission, and active Market Access when market-scoped. `Selected` means the server-bound Current Admin Market; route/header/local storage is never authority. All reads are bounded and server-projected. Every privileged or sensitive view/write appends an immutable audit event; ordinary navigation telemetry is not a substitute for domain audit.

## 2. Design System and routed-shell architecture

- Reuse `@ipoint/design-tokens/base.css` as the only token source and `@ipoint/ui` as the shared component foundation. Extend those packages through separately authorized, reusable components only; do not fork Admin-only tokens or sample screenshots.
- Replace the current six-value in-memory/hash page switch with a stable router. The route manifest is typed and carries route ID, path, navigation group, permissions, market classification, mobile policy, capability gate, loader, error boundary, and breadcrumb metadata. Browser refresh/back/forward and deep links must preserve only validated filters; bootstrap re-establishes actor, role, MFA/session, selected market, permissions, and capability availability from the server.
- Use a typed DTO client generated or authored from the accepted API contracts. Remove `JsonRecord`, snake/camel fallback probing, ad hoc path strings, client permission inference, and English-message branching. UI state is driven by stable error/capability codes and response DTOs.
- Shell: persistent desktop side navigation grouped as Overview, People, Commerce, Reviews, Network, Finance, Configuration, Redemption, Governance, Access Control, Security, and Account; responsive top bar always shows actor, role context, Current Admin Market, session/freshness state; mobile uses a focus-trapped drawer with escape/return-focus and touch targets. Navigation hiding is usability only; route and API guards remain authoritative.
- Every screen and section explicitly supports loading, empty, error, success, disabled, expired, suspended, permission denied, offline, retry, stale, conflict, and blocked-prerequisite states. `Unavailable` and valid numeric zero are distinct. An uncertain critical write retains the same idempotency key/payload for status lookup or safe retry.
- Accessibility acceptance: semantic landmarks/headings/tables/forms; keyboard-only operation; logical tab and roving-tab behavior; visible focus and focus restoration after route/modal/error; labelled fields and described validation; live regions without duplicate announcements; contrast compliant with WCAG 2.1 AA; reduced motion; 320px responsive reflow; automated axe plus manual keyboard/screen-reader spot checks.
- PWA per P7-OD-22: read-only monitoring and safe navigation only. No financial approval, no privileged mobile approval, no offline write queue, no background replay, and no service-worker caching of privileged payloads, sensitive projections, voucher material, KYC evidence, audit results, or auth/MFA secrets. Offline screens disclose the last safe shell state as stale without presenting cached values as current truth. Sensitive writes require full online desktop Admin Web.

## 3. Dashboard and basic-report metric definitions

All definitions are versioned server read models. “Today” and bucket boundaries use the selected market IANA timezone, while storage/query anchors are UTC. Queue/urgent metrics must be no older than 60 seconds; aggregate KPI/report metrics no older than 5 minutes. Missing, blocked, fabricated, or failed sources yield `Unavailable`, never zero. No metric uses first-page counts, client recomputation, or cross-currency addition.
