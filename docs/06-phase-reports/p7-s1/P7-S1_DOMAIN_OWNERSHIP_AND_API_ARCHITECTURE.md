## 3. Binding architecture rules

1. **Phase 7 owns Admin UX, safe read projections, queue composition, and orchestration.** It may translate a typed Admin request into an accepted owner command and translate owner results into an allowlisted Admin response.
2. **Frozen domains retain business truth.** Phase 1 owns merchant/package/MCP; Phase 2 owns member/KYC; Phase 3 owns wallet/reward/jobs; Phase 4 owns transactions; Phase 5 owns agent/commission; Phase 6 owns redemption/voucher/refund/fulfilment; Platform Access/Auth owns identity, sessions, RBAC, market grants, and privileged audit primitives.
3. **Phase 7 must not reproduce calculation or ledger logic.** No Admin controller computes reward, redemption value, service fee, MCP, iPoint, commission, inventory, or refund financial effects.
4. **Direct table writes from Admin controllers are prohibited where a canonical owner service exists.** A Phase 7 write adapter must call the canonical owner command. Direct SQL is limited to an authorized Phase 7-owned read projection or Phase 7-owned state, never frozen-domain mutation.
5. **Unsafe existing controllers are not made safe by being present.** Doubled/unregistered routes, identity-only guards, placeholder job data, immediate iPoint execution, and the refund ledger gap remain unavailable until their owner gate is independently accepted.
6. **Every read adapter enforces server-side permission, Current Admin Market, active Market Access, resource-market equality, masking, and bounded pagination.** A header, URL, local storage value, role label, or hidden control is context only.
7. **Every write adapter calls the canonical owner command and revalidates identity, MFA/step-up, permission, grant, target market, state/version, idempotency payload, and concurrency conditions inside the owner transaction.**
8. **UI hiding is never authorization.** An unauthorized or blocked request must fail through the API even if crafted directly.
9. **Unavailable is a first-class contract.** A blocked capability is represented by `availability: "UNAVAILABLE"`, `blockedPrerequisite`, and safe remediation reference. No active command route is registered before gate release.
10. **Commercial versions are prospective and immutable.** No new rule/rate/package/fee version recalculates or mutates historical wallet, ledger, transaction, assignment, quote, order, activation, or commission evidence.

## 4. API contract plan

### 4.1 Contract conventions

Every route below is a **future plan**, not an active implementation authorization. `ACTIVE AFTER BASE` means it may be implemented only after P7-S2 security/RBAC/market acceptance and its named sub-phase authorization. `RESERVED / NOT REGISTERED` means the command must not exist at runtime until its owner remediation gate is separately accepted. Existing safe Phase 1/2 routes may remain canonical; an Admin adapter is justified only where Current Admin Market bootstrap, masking, or a stable typed projection cannot be added without changing the frozen owner.

Market sources:

- `G`: global identity; no business-market parameter.
- `C`: server-bound Current Admin Market from the authenticated Admin session/context.
- `P`: `:marketId` path must equal `C` and an active grant.
- `R`: resource ID is resolved server-side and its market must equal `C`; client market fields are never authority.

Common error bundles (the table references these exact codes):

- `BASE`: `VALIDATION_FAILED`, `ADMIN_AUTH_REQUIRED`, `ADMIN_INELIGIBLE`, `MFA_REQUIRED`, `MFA_STEP_UP_REQUIRED`, `AUTH_PERMISSION_DENIED`, `AUTH_MARKET_ACCESS_DENIED`, `RESOURCE_NOT_FOUND`, `RESOURCE_MARKET_MISMATCH`, `STATE_CONFLICT`, `STALE_VERSION`, `IDEMPOTENCY_KEY_REQUIRED`, `IDEMPOTENCY_PAYLOAD_MISMATCH`, `CONCURRENCY_RETRYABLE`, `SERVICE_UNAVAILABLE`.
- `BLOCKED`: `ADMIN_CAPABILITY_UNAVAILABLE`, returning `blockedPrerequisite`, `ownerPhase`, and `remediationReference`; never synthetic success.
- `SENSITIVE`: `SENSITIVE_ACCESS_REASON_REQUIRED`, `SENSITIVE_FIELD_DENIED`, `EXPORT_NOT_ALLOWED`.
- `MFA`: `MFA_ENROLLMENT_REQUIRED`, `MFA_FACTOR_INVALID`, `MFA_CHALLENGE_INVALID`, `MFA_CHALLENGE_EXPIRED`, `MFA_RECOVERY_INVALID`, `MFA_REPLAY_DETECTED`, `MFA_RATE_LIMITED`.
- `MC`: `MAKER_CHECKER_SAME_ACTOR`, `CHECKER_ROLE_INSUFFICIENT`, `ADJUSTMENT_SOFT_CAP_EVIDENCE_REQUIRED`, `ADJUSTMENT_HARD_CAP_EXCEEDED`, `ADJUSTMENT_REPLACEMENT_REQUIRED`, `ADJUSTMENT_EXECUTION_FAILED`.

For `Idempotency = Required`, the key is operation-scoped, stored only in an approved hashed/confidential form, and the canonical payload hash is mandatory. Same key/same hash returns the original result; same key/different hash returns `IDEMPOTENCY_PAYLOAD_MISMATCH`. Reads do not require idempotency. All responses include a safe `requestId`; bounded reads also include `asOf`, cursor metadata, and an `availability` object where a source/action may be blocked.

## 5. Unavailable-state contract

Blocked features are discoverable through `GET /api/v1/admin/bootstrap` and safe read responses, not through executable command routes. The shared response shape is:

```json
{
  "availability": "UNAVAILABLE",
  "capability": "redemption.refund.approve",
  "blockedPrerequisite": "GATE-SEC-02",
  "ownerPhase": "PHASE_6",
  "remediationReference": "SEC-02 / P7-OD-19",
  "retryable": false
}
```

Rules:

1. A reserved route is absent from the registered controller/OpenAPI until its gate is accepted. If an older unsafe route exists, the Phase 7 client never calls or advertises it.
2. `Unavailable` is not HTTP success for a command attempt. A future disabled command boundary returns `423`/`ADMIN_CAPABILITY_UNAVAILABLE` only if a deliberately registered capability-gate endpoint is authorized; otherwise the route is `404` because it is not registered.
3. The UI shows the gate and read-only state, without a disabled control that suggests the operation is otherwise ready.
4. No client-side fallback, direct database action, Member/Merchant impersonation, or alternate doubled-prefix call is permitted.
