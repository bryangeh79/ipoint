# Phase 7 Admin Operations — Acceptance and Test Matrix

> **Status: DRAFT / UNDER_COMMAND_CENTER_REVIEW / NOT_IMPLEMENTATION_AUTHORIZATION**
>
> Documentation-only P7-S1E synthesis. These scenarios refine the frozen P7-AC-01..20 contract; they authorize no implementation, test, migration, CI, owner remediation, or later sub-phase.

## 1. Matrix conventions

- All HTTP scenarios use real registered `/api/v1` routes, strict DTOs, stable error codes, safe request IDs, real PostgreSQL, and server-derived actor/current-market context. UI-only denial is never sufficient.
- “No DB effect” means no domain, state, ledger, idempotency-result, or success audit mutation; a denied/security audit may still be required and is stated explicitly.
- Critical writes use operation-scoped key + canonical payload hash. Same key/same payload returns the committed result; same key/different payload returns `IDEMPOTENCY_REPLAY_MISMATCH`. Concurrent losers return the original result or stable conflict with no partial effect.
- Phase shown is the earliest phase where the scenario can run end-to-end. A phase dependency or gate does not authorize that phase.

## 4. Gate rule

A scenario may be implemented and run only in a separately authorized phase and only after its named prerequisite is accepted. At P7-S10, a blocked capability passes acceptance only by proving it remains explicitly unavailable and cannot be invoked; a blocked command is never waived by an attractive UI or a passing read-only test.
